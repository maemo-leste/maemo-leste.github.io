Maemo Leste - OS Image Generation with Forgejo CI

excalibur forgejo | 2026-04-01

Since adopting Forgejo for development, much of our workflow has shifted toward a more automated approach. This transition has been covered in earlier posts:

  • https://maemo-leste.github.io/maemo-leste-2025-daedalus-release.html
  • https://maemo-leste.github.io/maemo-leste-forgejo-migration.html

We have now moved OS image generation into Forgejo as well, using a Debian tool called debos.

Previously, image generation relied on a collection of Zsh scripts. While functional, this setup could be improved upon, as introducing new devices, or modifying existing images, or producing images was more time consuming than neccesary.

Debos

In favor of maintainability, we investigated a tool called debos for creating custom Debian-based OS images declaratively using YAML. In our case, each device (or device family) could maintain its own set of YAML build recipes. After some experimentation, we concluded that debos is flexible, allows for clearer organization of device-specific files, and thus easier customization of our images.

Under the hood, our use of debos summarized:

  1. debos starts a virtual machine using QEMU
  2. debos handles the chroot, and uses debootstrap for base filesystem creation
  3. debos installs packages, configuration files, and applies overlays
  4. debos produces an .img, ready to be dd'd

To re-iterate; this is all defined in YAML.

Forgejo CI

After migrating a few devices to this new debos setup, we integrated debos into Forgejo's CI/CD pipelines. Previously, generating an image for a single device could take up to 3 hours. With the new build infrastructure, we are now able to create images for 13 devices in 2 hours total, whilst not requiring any action on our end.

Build-time improved because the build process was restructured into two stages:

  1. Root filesystem (rootfs) generation
    • built once, and reused across multiple devices
  2. Device-specific image (imagefs) generation
    • layer additional packages and configuration on top of this shared base

This ultimately produces build artifacts that can be downloaded through the Forgejo web-interface.

In addition, it is a scheduled task - images are generated every week.

Image customization

Debos provides the flexibility to easily support all kinds of device-specific needs. For example, we have build recipes dedicated to disk layouts (MBR/GPT) with the option to configure for various partition setups: formats, sizes, offsets, and also easily assigning mount flags to those partitions (e.g. noatime).

This means that supporting future devices has now become easier, as e.g. disk needs are defined through debos options (bootstart=4MiB, partitiontable=mbr, rootstart=128MiB, partitionbootformat=ext2).

The customization on a per-device basis that may be needed:

  • Some devices require specific packages to be present (drivers, configuration)
  • Some devices require a specific kernel (still mainline, but we may require extra kernel config options, depending on the device)
  • Some devices require u-boot to be inserted at the start of the image
  • Some devices require a specific disk layout
  • Some devices require certain DTBs (device tree blobs) to be loaded during boot

Current devices

As for the devices themselves, we've added 3 new Olimex devices, fixed others (those that did not see a release in a while), and improved existing devices (Raspberry Pi / Pinephone).

As of writing, Forgejo generates images for:

  • Motorola Droid4
  • Motorola Droid3
  • Motorola Bionic
  • Motorola XT910
  • Motorola XT912
  • Motorola MZ617
  • Nokia N900
  • Raspberry Pi 3/4/5
  • Olimex A64-OLinuXino
  • Olimex A64-OLinuXino w/ eMMC
  • Olimex A20-OLinuXino-LIME2
  • Pinephone
  • Development VM (x86_64)

Additional devices

The build system has additional debos build configuration(s) in-place for 30+ more devices (e.g. Rockchip based devices), however, we do not generate images for them as it may give the impression these are well-supported. That said, if you have a device that is not supported, feel free to ask on our bugtracker (or IRC channel) for details on how to get started - perhaps we already have a configuration for your device.

Repository

The repository exists over at https://git.maemo.org/leste-cicd/debos-leste

Within this repository, you will find build.sh, which serves as an user-friendly utility for invoking debos. Use this bash script to generate an image locally.

Forgejo's CI does not use build.sh - instead it uses debos directly.

Future work

We are looking into libhybris as a way to expand Maemo Leste support to additional devices. Libhybris enables running a Linux userspace on top of certain Android-based hardware by reusing existing Android drivers. Further details will be covered in future blog posts.
